The JavaScript section is copied from the 0.7.0 `index.d.ts`. The Rust signatures below were copied at 0.6.1; [Upgrading](/docs/upgrading#070) lists what 0.7.0 changed in them, and what it adds to Rust (the audit fail mode, `Approvals`, `tz`) is on [Audit](/docs/audit), [Approvals](/docs/approvals) and [Concepts](/docs/concepts#time-zones). Pick a name to see it in the bench with a real example and what it returns. The first part is the `strig` crate: install it with `strig = "0.7"`; the default features are `audit`, and `dsl` and `dsl-fs` add the policy language. After it come `strig-sync` and its transports, `strig-axum`, `strig-server`, `strig-macros`, the npm package and the inspector.

The repository's `CHANGELOG.md` records what changed between versions; [Upgrading](/docs/upgrading) says what to change between releases. Strig was called Themis until 0.5.0: the crate `themis-auth` is now `strig`, and `use themis::` becomes `use strig::`, with the same code. The npm package and `strig-server` have no 0.6.0 release, so 0.6.1 was the first version of both.

## Engine

The decision engine. Immutable once built, and shared between threads. It holds only configuration; the grants come with each call.

<ApiGroup>
  <ApiItem id="engine-builder" name="Engine::builder" pick="builder" sig={"pub fn builder(catalog: impl Into<Arc<Catalog>>) -> EngineBuilder"}>
    Starts an engine from a catalog. The default strategy is `MostSpecific` and the relation depth is 32.
  </ApiItem>
  <ApiItem id="enginebuilder-build" name="EngineBuilder::build" sig={"pub fn build(self) -> Result<Engine, EngineError>"}>
    Builds the engine. Fails if an override exception names a permission outside the catalog.
  </ApiItem>
</ApiGroup>

<ApiWide>

| --- | --- | --- |

## Decision

There are no getters besides `is_allowed`: the reason, the deciding grant and the trail are public fields.

<ApiGroup>
  <ApiItem id="decision-struct" name="Decision" pick="decision" sig={"pub struct Decision { pub effect: Effect, pub reason: Reason, pub matched: Vec<String>, pub warnings: Vec<String> }"}>
    Allow or deny, why, every grant id that applied in source order, and problems that did not stop the decision.
  </ApiItem>
  <ApiItem id="decision-is-allowed" name="Decision::is_allowed" sig={"pub fn is_allowed(&self) -> bool"}>
    True only when `effect == Effect::Allow`.
  </ApiItem>
  <ApiItem id="reason" name="Reason" pick="reason" sig={"pub enum Reason"}>
    Why the decision came out that way. Serialized with the tag `kind`, in snake_case.
  </ApiItem>
</ApiGroup>

<ApiWide>

| Variant | It means |
| --- | --- |
| `Override { name: String }` | An override decided before the grants. |
| `Grant { grant_id: String, permission: String, rank: usize, strategy: String }` | A grant decided; this is the deciding grant. `rank` 0 is the most specific step. |
| `NoApplicableGrant` | No grant applied: default deny. |
| `UnknownPermission` | The permission is not in the catalog: deny. |
| `MissingPrerequisite { permission: String, prerequisite: String }` | Would be allowed, but a `depends_on` prerequisite is not allowed on the same resource. |

</ApiWide>

<Callout kind="note">
  `Reason` is not `#[non_exhaustive]`, so a `match` on it must name all five variants, `MissingPrerequisite` included.
</Callout>

<ApiGroup>
  <ApiItem id="effect" name="Effect" sig={"pub enum Effect { Allow, Deny }"}>
    The outcome of a decision or of a grant.
  </ApiItem>
  <ApiItem id="explanation" name="Explanation" sig={"pub struct Explanation { pub subject: Subject, pub permission: String, pub resource: Resource, pub effective: Vec<String>, pub path: Vec<Anchor>, pub roles: Vec<String>, pub overrides: Vec<OverrideStep>, pub grants: Vec<GrantTrace>, pub strategy: String, pub prerequisites: Vec<PrerequisiteStep>, pub decision: Decision }"}>
    The trail: the resource path, the roles in force, each override and each grant with its fate, then the decision. `prerequisites` holds the `depends_on` checks made once the permission was allowed.
  </ApiItem>
</ApiGroup>

## Strategy

<ApiGroup>
  <ApiItem id="strategy-trait" name="Strategy" pick="strategy" sig={"pub trait Strategy: Send + Sync { fn name(&self) -> &'static str; fn combine(&self, candidates: &[Candidate]) -> Option<usize>; fn native(&self) -> Option<NativeStrategy> { None } }"}>
    How applicable grants combine. A trait, with four unit structs. `native` says which of the four a strategy is, so a listing can reproduce it; with `None`, the default, the listing leaves a residue to check row by row.
  </ApiItem>
</ApiGroup>

<ApiWide>

| Rust type | In a policy | The deciding grant |
| --- | --- | --- |
| `MostSpecific` | `most_specific` | The most specific step with any grant decides; on it, deny wins. The default. |
| `DenyOverrides` | `deny_overrides` | Any deny wins. |
| `PermitOverrides` | `permit_overrides` | Any allow wins. |
| `FirstApplicable` | `first_applicable` | The first grant in source order decides. |

</ApiWide>

## Errors

A deny is never an error: `decide` always returns a `Decision`, and an unknown permission is `Reason::UnknownPermission`. Errors come from building and validating.

<ApiWide>

| Type | Variants | From |
| --- | --- | --- |
| `EngineError` | `UnknownPermission(String)` | `EngineBuilder::build` |
| `GrantError` | `EmptyId`, `UnknownPermission(String)`, `UnknownTargetKind(String)`, `TargetNotAllowed { permission, target }`, `OverrideOnly(String)`, `RelationsDisabled`, `UnknownFunction(String)`, `InvalidWindow(ValidityError)` | `Engine::validate_grant` |
| `SpecError` | `Catalog(CatalogErrors)`, `Roles(RbacError)`, `Engine(EngineError)` | `EngineSpec::build` |
| `QueryError` | `UnknownSubject(SubjectRef)`, `LimitExceeded { what, limit }`, `RelationDepthExceeded { grant_id }` | `check_for`, `who_can_on`, `access_of` |
| `dsl::Diagnostics` | A list of `Diagnostic { location, message, hint, related }` | `dsl::parse` |

</ApiWide>

## Real time: strig-sync

`strig-sync = "0.7"`. A permission change becomes a `Change` notice; the `Hub` delivers it to the sessions and caches of this instance and publishes it on a `Transport` for the others. A notice never carries grants: whoever receives it reloads from its own source.

<ApiGroup>
  <ApiItem id="hub-builder" name="Hub::builder" sig={"pub fn builder() -> HubBuilder\npub fn new() -> Self"}>
    A hub with a transport, or a local-only hub with `Hub::new`. The builder takes `capacity(usize)`, `origin(impl Into<String>)`, `transport(impl Transport)` and `shared_transport(Arc<dyn Transport>)`, then `build() -> Hub`. The channel capacity is 1024 and the origin is random until you set one.
  </ApiItem>
  <ApiItem id="hub-publish" name="Hub::publish" pick="hub" sig={"pub async fn publish(&self, mut change: Change) -> Result<Change, TransportError>"}>

  </ApiItem>
  <ApiItem id="hub-spawn-relay" name="Hub::spawn_relay" sig={"pub fn spawn_relay(&self) -> RelayHandle"}>

  </ApiItem>

## HTTP API

`strig-server` speaks JSON over HTTP. A request and its answer:

```bash
curl -s localhost:8080/v1/check \
  -H 'content-type: application/json' \
  -H 'x-strig-timeout-ms: 500' \
  -d '{"subject":{"kind":"user","id":"ana"},"permission":"document.view","resource":{"kind":"document","id":"d1"}}'
```

```json
{"decision": {"effect": "allow"}, "evaluated_at": 1700000000000, "requested_at": 1700000000000}
```

All times are milliseconds since the Unix epoch, UTC. The server decides with its own clock: `at` in a body is echoed for audit and never used to decide. There is no authentication and no rate limiting; put the server behind your gateway.

**Fail closed.** Only `200` from a decision route is a success. A network error, a timeout, any other status and an unreadable `200` all mean no access. A deny is a normal `200` with `effect: "deny"`.

### Routes

<ApiWide>

| Route | Body | Answer |
| --- | --- | --- |
| `POST /v1/check` | `subject`, `permission`, `resource`, optional `env`, `at`, `min_revision` | `decision`, `evaluated_at`, `requested_at`, and `revision` when the source tracks one. |
| `POST /v1/check/batch` | `{"checks": [...]}` | `{"results": [...]}` in request order. All or nothing: a failure is one error, never partial results. |
| `POST /v1/list` | `subject`, `permission`, `kind`, optional `layout`, `resources`, `env`, `at` | `kind`, `permission`, `exact`, `shape`, `residual`, `warnings`, `evaluated_at`, and `ids` when `resources` was sent. Never read `residual` as an allow. |
| `POST /v1/who` | `permission`, optional `resource`, `env`, `at` | `entries` (each with a typed `subject` and the `via` that grants it), `except`, `evaluated_at`. |
| `POST /v1/access` | `resource`, `env`, `at` | Who holds which permission on the resource, with the path that decided each. |
| `GET /health/live` | none | `200 {"status":"live"}` while the process runs. |
| `GET /health/ready` | none | `200 {"status":"ready"}` when the grant source answers; otherwise `503`, so the instance leaves the pool. |

</ApiWide>

`shape.type` in a list answer is `nothing`, `kind` (with `except`), `ids`, `within` (with `anchors`) or `compound` (with `expr`).

### Headers

| Header | Effect |
| --- | --- |
| `x-strig-timeout-ms: <n>` | Deadline of this request, capped at the server's ceiling (default 10 s; default deadline 2 s). `0`, a negative number or text is `400 invalid_request`. A passed deadline is `503 deadline_exceeded`. |
| `x-strig-min-revision: <scope>@<value>` | Answer only from data at that revision or later (any route; `check` and `check/batch` also take `min_revision`). A source that is behind is polled until the deadline, then `503 revision_not_reached`. Another scope, or no revision at all, is `503 revision_mismatch` at once. A malformed token is `400 invalid_request`. |
| `x-strig-reason: true` | On the AuthZEN and Envoy routes with `with_reasons(true)`: adds a fixed reason code to the answer. |

### AuthZEN

```bash
curl -s localhost:8080/access/v1/evaluation \
```

```json
{"decision": true}
```

| --- | --- |

| `POST /access/v1/evaluations` | Top-level `subject`, `action`, `resource`, `context` are defaults an item overrides. `options.evaluations_semantic` is `execute_all` (default), `deny_on_first_deny` or `permit_on_first_permit`; anything else is `400`. |
| `POST /access/v1/search/subject` | Subjects of `subject.type` that hold `action.name` on `resource`. |

| AuthZEN | Strig |
| --- | --- |

| `subject.properties` | Attributes. `roles` (default name) holds the roles, as strings or `{role, scope?, valid_from?, valid_until?}`; `principals` holds principal names. Neither becomes an attribute. |
| `resource.type`, `resource.id` | The first step of the path, `type:id`. |

`decision` is `true` only for an allow; a permission outside the catalog is `200 {"decision": false}`. With `with_reasons(true)` and the header `x-strig-reason: true`, `context.reason` is one of `override`, `grant`, `no_applicable_grant`, `unknown_permission`, `missing_prerequisite`; it never names a grant, role or permission. Errors use the `/v1` error body with the statuses of the spec: `400` for a request that does not fit, `500` for everything the server could not decide.

Searches are sorted and take `page: {token?, limit?}` (`limit` defaults to and is capped by `with_max_page_size`, 1000); the answer carries `page: {next_token, count, total}`, and `next_token` is `""` on the last page. A token is bound to its request: change the entity, the context or the limit and it is `400`. Subject search sets `context.incomplete` to `true` when a party that is not a subject of a type (role, principal, userset, wildcard, `anyone`) was left out. `signed_metadata`, `capabilities`, tenant suffixes of the well-known URI, `action.properties` and `page.properties` are not read.

### Envoy external authorization

With the `envoy` feature, `DecisionServer::envoy_service(EnvoyConfig)` builds the `envoy.service.auth.v3.Authorization` gRPC service over the same source, clock, limits and work slots as the HTTP routes. Take it before `router()`, which consumes the server. Without the feature the crate has no `tonic` or `prost` in its build.

<ApiWide>

| `CheckRequest` | Strig |
| --- | --- |
| `attributes.request.http.method` and `path` | The first route whose methods and pattern match decides. A path with dot segments, an empty middle segment, an encoded `/`, `\` or NUL, invalid UTF-8 or more than 64 segments matches no route. |
| A header (`with_subject_header`) or filter metadata (`with_subject_metadata`) | The subject id, of the kind `with_subject_kind` (default `user`), with the `authenticated` principal. A value that is empty, over 512 bytes or holds a comma is no subject. |

Patterns start with `/`; a segment is a literal, `{name}` (one segment, captured), `*` (one segment) or, last, `**` (the rest). Methods are `*` or a list such as `GET,HEAD`. Rules are tried in the order they were added. The adapter trusts the subject and roles it reads: Envoy must set those headers itself and overwrite what the client sent.

| Case | `status.code` | HTTP | `x-strig-reason` (with `with_reasons(true)`) |
| --- | --- | --- | --- |
| The engine allows, or the route is `public` | `OK` (0) | | |
| The engine denies | `PERMISSION_DENIED` (7) | 403 | `denied` |
| No route matches | same | 403 | `no_route` |

| The resolver does not know the resource | same | 403 | `unknown_resource` |

| No HTTP attributes, or a template that cannot be filled | same | 403 | `bad_request` |

A `public` route decides nothing and does not read the source, so it allows even while the source is down. Every error the binding throws has a stable `error.code`, the same on both backends: `INVALID_ARGUMENT`, `INVALID_INPUT`, `INVALID_SPEC`, `INVALID_GRANT`, `UNKNOWN_SUBJECT`, `QUERY_LIMIT_EXCEEDED`, `RELATION_DEPTH_EXCEEDED`, `QUERY_ERROR`, `UNKNOWN_INVARIANT`, `REENTRANT_CALL`, the `EXCLUSIVE_*` and `DSL_*` codes, and `INTERNAL`. ## Inspector: strig-inspect

Not published on crates.io and outside the workspace default members: install it from a clone with `cargo install --path crates/strig-inspect`, or add `--no-default-features` for the terminal commands only. It explains decisions, simulates grants, builds the access matrix and reads an audit trail. Its library API is small and not a stable contract, so only the commands are listed.

<ApiGroup>
