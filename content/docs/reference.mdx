Every signature is copied from the source at 0.6.1. Pick a name to see it in the bench with a real example and what it returns. The first part is the `strig` crate: install it with `strig = "0.6"`; the default features are `audit`, and `dsl` and `dsl-fs` add the policy language. After it come `strig-sync` and its transports, `strig-axum`, `strig-server`, `strig-macros`, the npm package and the inspector.

The crate ships no changelog, so no item here carries an "Added in" badge. Strig was called Themis until 0.5.0: the crate `themis-auth` is now `strig`, and `use themis::` becomes `use strig::`, with the same code.

## Engine

The decision engine. Immutable once built, and shared between threads. It holds only configuration; the grants come with each call.

<ApiGroup>
  <ApiItem id="engine-builder" name="Engine::builder" pick="builder" sig={"pub fn builder(catalog: impl Into<Arc<Catalog>>) -> EngineBuilder"}>
    Starts an engine from a catalog. The default strategy is `MostSpecific` and the relation depth is 32.
  </ApiItem>
  <ApiItem id="enginebuilder-build" name="EngineBuilder::build" sig={"pub fn build(self) -> Result<Engine, EngineError>"}>
    Builds the engine. Fails if an override exception names a permission outside the catalog.
  </ApiItem>
</ApiGroup>

<ApiWide>

| Builder method | Signature | What it does |
| --- | --- | --- |
| `roles` | `pub fn roles(mut self, roles: RoleGraph) -> Self` | Sets role inheritance. |
| `relations` | `pub fn relations(mut self, schema: RelationSchema) -> Self` | Turns on ReBAC with this schema. |
| `conditions` | `pub fn conditions(mut self, registry: ConditionRegistry) -> Self` | Registers custom condition functions. |

## Decision

There are no getters besides `is_allowed`: the reason, the deciding grant and the trail are public fields.

<ApiGroup>
  <ApiItem id="decision-struct" name="Decision" pick="decision" sig={"pub struct Decision { pub effect: Effect, pub reason: Reason, pub matched: Vec<String>, pub warnings: Vec<String> }"}>
    Allow or deny, why, every grant id that applied in source order, and problems that did not stop the decision.
  </ApiItem>
  <ApiItem id="decision-is-allowed" name="Decision::is_allowed" sig={"pub fn is_allowed(&self) -> bool"}>
    True only when `effect == Effect::Allow`.
  </ApiItem>
  <ApiItem id="reason" name="Reason" pick="reason" sig={"pub enum Reason"}>
    Why the decision came out that way. Serialized with the tag `kind`, in snake_case.
  </ApiItem>
</ApiGroup>

<ApiWide>

| Variant | It means |
| --- | --- |
| `Override { name: String }` | An override decided before the grants. |
| `Grant { grant_id: String, permission: String, rank: usize, strategy: String }` | A grant decided; this is the deciding grant. `rank` 0 is the most specific step. |
| `NoApplicableGrant` | No grant applied: default deny. |
| `UnknownPermission` | The permission is not in the catalog: deny. |
| `MissingPrerequisite { permission: String, prerequisite: String }` | Would be allowed, but a `depends_on` prerequisite is not allowed on the same resource. |

</ApiWide>

<Callout kind="note">
  `Reason` is not `#[non_exhaustive]`, so a `match` on it must name all five variants, `MissingPrerequisite` included.
</Callout>

<ApiGroup>
  <ApiItem id="effect" name="Effect" sig={"pub enum Effect { Allow, Deny }"}>
    The outcome of a decision or of a grant.
  </ApiItem>
  <ApiItem id="explanation" name="Explanation" sig={"pub struct Explanation { pub subject: Subject, pub permission: String, pub resource: Resource, pub effective: Vec<String>, pub path: Vec<Anchor>, pub roles: Vec<String>, pub overrides: Vec<OverrideStep>, pub grants: Vec<GrantTrace>, pub strategy: String, pub prerequisites: Vec<PrerequisiteStep>, pub decision: Decision }"}>
    The trail: the resource path, the roles in force, each override and each grant with its fate, then the decision. `prerequisites` holds the `depends_on` checks made once the permission was allowed.
  </ApiItem>
</ApiGroup>

## Strategy

## Errors

A deny is never an error: `decide` always returns a `Decision`, and an unknown permission is `Reason::UnknownPermission`. Errors come from building and validating.

<ApiWide>

| Type | Variants | From |
| --- | --- | --- |
| `EngineError` | `UnknownPermission(String)` | `EngineBuilder::build` |
| `GrantError` | `EmptyId`, `UnknownPermission(String)`, `UnknownTargetKind(String)`, `TargetNotAllowed { permission, target }`, `OverrideOnly(String)`, `RelationsDisabled`, `UnknownFunction(String)`, `InvalidWindow(ValidityError)` | `Engine::validate_grant` |
| `SpecError` | `Catalog(CatalogErrors)`, `Roles(RbacError)`, `Engine(EngineError)` | `EngineSpec::build` |
| `QueryError` | `UnknownSubject(SubjectRef)`, `LimitExceeded { what, limit }`, `RelationDepthExceeded { grant_id }` | `check_for`, `who_can_on`, `access_of` |
| `dsl::Diagnostics` | A list of `Diagnostic { location, message, hint, related }` | `dsl::parse` |

</ApiWide>

## Real time: strig-sync

`strig-sync = "0.6"`. A permission change becomes a `Change` notice; the `Hub` delivers it to the sessions and caches of this instance and publishes it on a `Transport` for the others. A notice never carries grants: whoever receives it reloads from its own source.

<ApiGroup>
  <ApiItem id="hub-builder" name="Hub::builder" sig={"pub fn builder() -> HubBuilder\npub fn new() -> Self"}>
    A hub with a transport, or a local-only hub with `Hub::new`. The builder takes `capacity(usize)`, `origin(impl Into<String>)`, `transport(impl Transport)` and `shared_transport(Arc<dyn Transport>)`, then `build() -> Hub`. The channel capacity is 1024 and the origin is random until you set one.
  </ApiItem>
  <ApiItem id="hub-publish" name="Hub::publish" pick="hub" sig={"pub async fn publish(&self, mut change: Change) -> Result<Change, TransportError>"}>
    Stamps origin, sequence and time, delivers locally and publishes on the transport. Local delivery happens even when the transport fails; the error comes back to the caller.
  </ApiItem>
  <ApiItem id="hub-spawn-relay" name="Hub::spawn_relay" sig={"pub fn spawn_relay(&self) -> RelayHandle"}>
    Listens to the transport in the background and delivers what the other instances publish. It reconnects with backoff from 100 ms to 5 s and emits `Resync` on each reconnection. It stops when the `RelayHandle` is dropped.
  </ApiItem>
  <ApiItem id="hub-on-change" name="Hub::on_change, Hub::subscribe" sig={"pub fn on_change(&self, sink: Arc<dyn ChangeSink>)\npub fn subscribe(&self) -> broadcast::Receiver<Change>"}>
    A synchronous sink for every change, or a broadcast receiver. A closure `Fn(&Change)` is a `ChangeSink`, and so is `CapabilityCache`.
  </ApiItem>
  <ApiItem id="hub-schedule-expiry" name="Hub::schedule_expiry" sig={"pub fn schedule_expiry(&self, boundary_ms: u64, now_ms: u64, change: Change) -> bool"}>
    Delivers `change` on this instance when the clock reaches `boundary_ms`, so a grant that starts or stops recomputes without a write. It never goes through the transport. Returns `false` outside a Tokio runtime.
  </ApiItem>
</ApiGroup>

## Decision server: strig-server

`strig-server = "0.6"`, with the `client` feature on by default. The server answers over HTTP from a `DecisionSource` you provide and decides with its own clock. It does no authentication and no rate limiting: put it behind your gateway. Any answer that is not a `200` from a decision route means no access.

## Policies at compile time: strig-macros

`strig-macros = "0.6"`. A policy that does not validate does not build. Add `strig` with the `dsl` feature to your own `Cargo.toml`, and use the same version of both: `strig-macros` pins `strig` with `=`.

<ApiGroup>
  <ApiItem id="policy-macro" name="policy!" pick="policy" sig={"policy!(\"<policy text>\")"}>
    Compiles and validates a policy written as a text literal. The result is a `strig::dsl::Policy`. An error stops the build and points at the literal, with `policy:line:column` counted inside the text. Prefer a raw string for anything with several lines.
  </ApiItem>
  <ApiItem id="include-policy-macro" name="include_policy!" sig={"include_policy!(\"<path>\")"}>
    The same, from a file relative to the `CARGO_MANIFEST_DIR` of the caller. The file must be inside the crate, and paths through `target/` or a hidden component are refused, as are files over 4 MiB. An error reads `path:line:column: message`.
  </ApiItem>
</ApiGroup>

The expansion embeds the validated policy as JSON and reads it back, so the policy text is never parsed at runtime but the JSON is, on each evaluation. In a hot path, keep it in a `static` with `LazyLock`.

## Inspector: strig-inspect

Not published on crates.io and outside the workspace default members: install it from a clone with `cargo install --path crates/strig-inspect`, or add `--no-default-features` for the terminal commands only. It explains decisions, simulates grants, builds the access matrix and reads an audit trail. Its library API is small and not a stable contract, so only the commands are listed.

<ApiGroup>

    `explain` prints the trace of one decision. `matrix` shows who can do what on a resource, and which cells change when you disable or add a grant. `audit` lists a trail, checks the hash chain and re-evaluates the decisions. `fmt` formats `.strig` files; `--check` only lists them and exits with 1 if any would change. A scenario is a JSON file with `spec`, `grants`, `tuples`, `env`, `subjects` and `resources`.
